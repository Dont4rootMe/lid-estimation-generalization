# Рабочий процесс

## Начало задачи

1. Прочитать `AGENTS.md`, `PROJECT_STATE.md` и предметный документ.
2. Выполнить `git status --short --ignored` и открыть актуальную версию файлов,
   которые будут затронуты.
3. Отделить запрошенную работу от несвязанных пользовательских изменений.
4. Для независимых аудитов подагенты по умолчанию не редактируют общие файлы;
   основной агент интегрирует выводы после сверки.

Локальные `paper/`, `artifacts/` и `output/` игнорируются Git и могут
отсутствовать у другого агента или checkout. Их наличие проверяется явно; путь
из старого сообщения не считается доказательством наличия артефакта.

## Рукопись

- Русский текст является рабочей master-версией.
- `paper/ru/main.tex` содержит шапку, аннотацию, порядок `\input` и
  библиографию. Содержательный текст редактируется в `sections/*.tex`.
- Каждому приложению соответствует отдельный файл в `sections/appendix/`.
- Перед вводом нового русского термина проверять `paper/ru/TERMINOLOGY.md`.
- По авторскому решению от 2026-09-05 раздел 2 — исключительно Related
  Work. Он сопоставляет литературу, но не вводит постановку, обозначения,
  собственные определения или выводы формул. Не объединять его с Background;
  необходимую постановку давать в начале теоретического раздела.
- Последний авторский бюджет от 2026-09-05 — не более семи страниц на весь
  текущий основной текст до литературы. В главе 3 сохранять последовательный
  аргумент к мастер-теореме; в главе 4 давать особенности семейства, итоговое
  следствие и прямую ссылку на модельное приложение. Промежуточные выкладки,
  технические леммы и доказательства помещать в адресные приложения.
  Не достигать лимита уменьшением кегля, полей или интервалов.
- Стиль — формальный и безличный. Не использовать разговорные слоганы,
  необоснованное «для любой модели», коллективное «мы показали» и архитектурное
  название вместо математического условия.
- Интуитивное наблюдение вводится до тяжёлой формализации; theorem preview
  обязан явно указывать масштаб, предположения и область действия.
- Не изменять английскую версию автоматически вслед за русской.

Локальная сборка:

```bash
cd paper/ru
./build.sh
```

После изменения LaTeX проверяются лог сборки, разрешение ссылок и визуальный
рендер всех затронутых страниц. Пользовательские PDF-артефакты помещаются в
`output/pdf/`; build-файлы и `output/` не добавляются в Git.

## Код и эксперименты

Базовая проверка:

```bash
uv sync --frozen --group dev
uv run pytest
```

Для локальной правки запускается минимальный релевантный набор тестов, затем
полный набор в соответствии с риском. Экспериментальные конфигурации задаются
Hydra YAML; новые скрытые параметры командной строки или TOML-конфигурации для
научных запусков не добавляются.

Любой reported learned result должен быть связан с checkpoint, resolved
training config, dataset/preprocessing identity и seed через контракт из
`docs/LEARNED_BUNDLES.md`. Oracle и learned evidence маркируются отдельно.

## Обновление документации

- изменение математического scope → `THEORY_CONTRACT.md` + `DECISIONS.md`;
- изменение текущей фазы → `PROJECT_STATE.md`;
- изменение model/readout matrix → `docs/MODEL_MATRIX.md`;
- изменение experiment gates → `docs/EXPERIMENT_PROTOCOL.md`;
- изменение artifact schema → `docs/LEARNED_BUNDLES.md`;
- новый устойчивый предметный документ → ссылка из `docs/agent/README.md`.

Документация обновляется в том же изменении, что код или теория. Временный лог
одного запуска не превращается в постоянный документ.
