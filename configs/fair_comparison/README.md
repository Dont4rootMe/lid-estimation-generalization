# Общий протокол сравнения

Этот запуск объединяет исправления обычных данных и Arrows. Правило архитектуры
зависит от представления данных и применяется ко всем методам на нём.
Полная матрица: 39 представлений × 11 нативных интерфейсов = 429 обучений.
Команды выполняются из исходного checkout с установленными upstream/train
зависимостями. Новый протокол не меняет воспроизводимые старые defaults.

| Данные | Десять векторных интерфейсов | NF |
|---|---|---|
| Коэффициенты и линейно отрендеренные PCA-наборы | Один spectral residual core, width512, одинаковая fit-only covariance нормировка | Обратимый RealNVP в той же covariance-оболочке; ширина по фактической ёмкости общего core |
| Пространственные изображения: Arrows и Fashion-MNIST/преобразования | Один U-Net width32 и общая Gaussian-tail параметризация | Обратимый image RealNVP с восемью U-Net conditioners; ширина выбирается по общему числу параметров |

U-Net у NF — conditioner обратимых coupling-слоёв. Сам NF остаётся точно
нормированной плотностью с обратным отображением и полным Jacobian determinant.
Это не одинаковая генеративная архитектура с diffusion. На RGB Arrows общий
vector U-Net имеет 893507 параметров, NF — 908928 (разница 1,73%). На одноканальных
изображениях это 892353 и 905008 (1,42%). Выбор ширины не использует LID или MAE.
В covariance-наборах ёмкость считается после определения ранга по fit-данным;
истинный LID для этого не используется. Разница параметров NF ограничена 10%.

У всех методов одинаковы seed0, 128000 обновлений, batch256, AdamW2e-4,
weight decay1e-6, gradient clipping1 и float32 без TF32. Пары Z,−Z дают 256
вычисленных примеров, то есть 128 различных чистых наблюдений за шаг. Последние
8000 обновлений используют cosine до 1% LR и EMA0,999. **VP также использует
этот общий рецепт**, без прежних исключений для clipping, cosine и EMA.
Сохранены нативные targets, веса loss и распределения времени/шума: это
определения сравниваемых методов, а не настройки backbone. Равны обновления
и число примеров; равенство FLOPs не заявлено, фактическое время сохраняется.

Fit/holdout выбираются одним source-train splitmix64 seed0 правилом. Все методы
видят одинаковые объекты и используют только fit для нормировки. Веса выбирает
минимальный native holdout loss, с одинаковой частотой проверок и доступом к
raw/EMA состояниям. Known-LID λ выбирается прежним supervised bounded-v2
правилом на одной физической сетке, без дополнительного уточнения для отдельных
методов. Для векторных данных trace точный в обученной оболочке у всех методов;
для изображений у всех 64 одинаково заданные Hutchinson-пробы. NF OLS5 остаётся
отдельным нативным readout, точная производная в float64 сохраняется дополнительно.
Test открывается только после записи checkpoint/scale receipt и использует все
исходные test-запросы. Успех этого протокола не означает uniform λ→0 convergence.

В задачах без известных LID сохранён target-free reference-mean Kneedle.
Зависимые E1/E5 ячейки обязаны получить scale из завершённой reference-ячейки
того же метода и протокола. Они не могут подбирать шкалу заново по своим
результатам. Отсутствие knee сохраняется как `selection_failed`.

## Исправления измерений от 2026-09-11

Версия `dataset_routed_native_comparison_measurements_v2` сохраняет архитектуры,
обучение и основной bounded-v2 выбор λ. Она восстанавливает отсутствовавший в
первом общем runner pointwise Kneedle для Known-LID и добавляет отдельную
диагностику сравнения на одинаковых кандидатах. До открытия test сохраняются
правила автоматического выбора и supervised-выбор на общей сетке.

| Поле `diagnostic_metrics` | Правило выбора | Кандидаты |
|---|---|---|
| `kneedle_legacy` | Pointwise Kneedle без LID-меток, точные параметры прежнего FLIPD | 22 VP-времени, физические λ≈0,210656–3,229097 |
| `kneedle_common_grid` | То же правило и reference-VP-time координата | 29 полушагов log2 λ от1/256 до64 |
| `supervised_common_grid` | Один минимум MAE на source-train holdout; заморожен перед test | Те же29 кандидатов |

Основная строка `metrics.full` или `metrics.ols5` по-прежнему использует bounded-v2.
Она может отличаться от `supervised_common_grid`: bounded-v2 расширяет только
сторону, на которой выиграла исходная сетка. Сравнение двух Kneedle-строк меняет
и диапазон, и плотность сетки; оно не изолирует только ширину диапазона.
Модификация сетки не доказывает, что найденный изгиб соответствует истинному LID.

Kneedle0.8.6 фиксирован; S1, convex/decreasing, online=false, interp1d.
При отсутствии knee pointwise-метод возвращает ambient dimension, как прежний
baseline. MAE включает все запросы, в том числе fallback. `fallback_n` считает
отказы, `boundary_n` — найденные knees на концах сетки, `selected_lambda_counts`
сохраняет распределение выбранных масштабов. Граница не переименовывается в
отказ задним числом. Полные кривые, индексы и флаги сохранены в
`test_scale_curves.npz`, ответы/цели/ID — в `test_predictions.npz`.

Для E1/E5 сохраняется прежний mean-Kneedle на50 кандидатах полного диапазона;
узкая22-точечная сетка к нему не относится. Перед обучением зависимой ячейки
проверяются артефакты reference, допустимость масштаба и одинаковый бюджет.
Копия reference receipt сохраняется с хешем. Отказ переносит обе причины:
`reference_selection_failed` и исходную `reference_failure_reason`.
Завершённое обучение с отказом выбора остаётся отсутствующим LID-измерением:
`measurement_status=selection_failed`, пустые метрики. Никакой λ по умолчанию
не подставляется. Агрегация показывает `coverage` для selected, scale_unresolved
и selection_failed и возвращает `complete_with_selection_issues`, если не все
выборы успешны и разрешены по границе.

Перед публикацией `complete.json` runner повторяет выбор по сохранённому holdout,
проверяет идентичность frozen receipt и пересчитывает все метрики/pointwise
решения из массивов. Агрегатор повторяет эти проверки и сверяет reference-цепочки.
Это проверка согласованности артефактов, не доказательство качества обучения.

## Команды

Проверить все маршруты архитектуры, не запуская обучение:

```bash
python -m experiments.fair_campaign matrix --output artifacts/fair/matrix.json
```

Запустить одну ячейку нового сравнения:

```bash
CUDA_VISIBLE_DEVICES=0 python -m experiments.fair_campaign run \
  --variant vp_diffusion --cell e2/e2_arrows/dataset \
  --canonical-root data/lid_benchmarks_exact/benchmarks \
  --output artifacts/fair/runs/vp_diffusion/e2_arrows_dataset
```

Синтаксис одинаков для всех 11 вариантов, перечисленных в `matrix.json`.
Для E3/E4 укажите `--generated-root data/generated_benchmarks`. Запускайте
независимые ячейки на разных GPU; reference-ячейки должны закончиться раньше
зависимых. Например, для E1 шага2 добавляется
`--reference artifacts/fair/runs/vp_diffusion/e1_step1/complete.json`.
Каждый output должен быть новым; исходные checkpoints и progress сохраняются.

Короткая техническая проверка: к той же команде добавьте `--preflight --steps 20`
и отдельный output. Она использует ограниченные подмножества fit/holdout/test
и сокращённый бюджет; **такие результаты запрещены в benchmark-агрегации**.

Агрегация после завершения полной выбранной матрицы:

```bash
python -m experiments.fair_campaign aggregate \
  --root artifacts/fair/runs --scope all --output artifacts/fair/results.json
```

`--scope known_lid` проверяет полный Known-LID поднабор. Агрегатор требует все
сочетания, единые исходники/протокол, правильные бюджеты, фактические configs,
согласованные данные/индексы/нормировку/test-count, сохранённые веса и неизменные
selection/prediction receipts. Он отклоняет старые результаты, незавершённую
матрицу, дубликаты и preflight. Результаты прежних диагностик не становятся
новыми результатами от одного изменения конфигурации: нужен реальный перезапуск.

Отдельно проверить воспроизводимость измерений завершённого запуска, включая
явно помеченный preflight:

```bash
python -m experiments.fair_campaign verify --receipt artifacts/fair/runs/example/complete.json
```

Проверки нового кода:

```bash
python -m pytest -q tests/unit/test_fair_comparison.py tests/unit/test_fair_measurements.py
```

Они проверяют все маршруты, сопоставление параметров, одинаковые нативные
posterior/Jacobian после преобразований, сохранение Arrows VE/RF формул и
градиентов, обратимость NF и соответствие полного determinant автодифференцированию.
