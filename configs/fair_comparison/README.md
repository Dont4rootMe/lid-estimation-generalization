# Общий протокол сравнения

Текущий протокол `full_ambient_native_comparison_non_gaussian_v6` выполняет
решение автора от 11 сентября: ни одна представленная координата не удаляется
подогнанной проекцией. Правило архитектуры зависит от представления данных
и применяется ко всем методам на нём. Прежние projected результаты исключены
из статьи, в том числе из ablations; старые checkpoints сохранены как история.
Полная матрица: 39 представлений × 13 нативных интерфейсов = 507 обучений.
Команды выполняются из исходного checkout с установленными upstream/train
зависимостями. Новый протокол не меняет воспроизводимые старые defaults.

| Данные | Двенадцать векторных интерфейсов | NF |
|---|---|---|
| Полные представленные коэффициенты | Один spectral residual core width512; все входные и выходные координаты обучаемы, только scalar fit нормировка и schedule scaling | Обратимый RealNVP во всей ambient размерности, без аналитического нормального дополнения |
| Все изображения, включая PCA-рендеры, Arrows и Fashion-MNIST | Один U-Net width32 и общая Gaussian-tail параметризация, без проекции пикселей | Обратимый image RealNVP с восемью U-Net conditioners; ширина выбирается по общему числу параметров |

U-Net у NF — conditioner обратимых coupling-слоёв. Сам NF остаётся точно
нормированной плотностью с обратным отображением и полным Jacobian determinant.
Это не одинаковая генеративная архитектура с diffusion. На RGB Arrows общий
vector U-Net имеет 893507 параметров, NF — 908928 (разница 1,73%). На одноканальных
изображениях это 892353 и 905008 (1,42%). Выбор ширины не использует LID или MAE.
Для коэффициентов ёмкость определяется полной входной размерностью;
ковариация и ранг данных не оцениваются. Разница параметров NF ограничена 10%.

У всех методов одинаковы seed0, 128000 обновлений, batch256, AdamW2e-4,
weight decay1e-6, gradient clipping1 и float32 без TF32. Пары Z,−Z дают 256
вычисленных примеров, то есть 128 различных чистых наблюдений за шаг. Последние
8000 обновлений используют cosine до 1% LR и EMA0,999. **VP также использует
этот общий рецепт**, без прежних исключений для clipping, cosine и EMA.
Сохранены нативные targets, веса loss и распределения времени/шума: это
определения сравниваемых методов, а не настройки backbone. Равны обновления
и число примеров; равенство FLOPs не заявлено, фактическое время сохраняется.

Fit/holdout выбираются одним source-train splitmix64 seed0 правилом. Все методы
видят одинаковые объекты и используют только fit для нормировки. Веса выбирает
минимальный native holdout loss, с одинаковой частотой проверок и доступом к
raw/EMA состояниям. Known-LID λ выбирается минимумом holdout MAE по всем29
кандидатам λ=2^(k/2), k=−16,…,12: от1/256 до64. Основной pointwise Kneedle
получает ровно тот же массив кандидатов у каждого метода. Для векторных данных
trace точный по всем ambient координатам у всех методов;
для изображений у всех 64 одинаково заданные Hutchinson-пробы. NF OLS5 остаётся
отдельным нативным readout, точная производная в float64 сохраняется дополнительно.
Test открывается только после записи checkpoint/scale receipt и использует все
исходные test-запросы. Успех этого протокола не означает uniform λ→0 convergence.

В задачах без известных LID сохранён target-free reference-mean Kneedle.
Зависимые E1/E5 ячейки обязаны получить scale из завершённой reference-ячейки
того же метода и протокола. Они не могут подбирать шкалу заново по своим
результатам. Отсутствие knee сохраняется как `selection_failed`.

## Исправления измерений от 2026-09-11

Версия выбора `common_grid_v3` сохраняет архитектуры
и обучение. По решению автора оба основных Known-LID selector используют
одинаковые29 кандидатов: supervised проверяет их все по holdout MAE, Kneedle
использует кривую без LID-меток. Одностороннее расширение bounded-v2 заменено
полным поиском на этой фиксированной сетке. До открытия test сохраняются
правила автоматического выбора и выбранный supervised λ.

| Поле `diagnostic_metrics` | Правило выбора | Кандидаты |
|---|---|---|
| `kneedle_legacy` | Только историческое воспроизведение прежнего FLIPD | 22 VP-времени, физические λ≈0,210656–3,229097 |
| `kneedle_common_grid` | Основной автоматический Kneedle; reference-VP-time координата | 29 полушагов log2 λ от1/256 до64 |
| `supervised_common_grid` | Основной минимум MAE на source-train holdout; заморожен перед test | Те же29 кандидатов |

Основная строка `metrics.full` или `metrics.ols5` использует полный29-grid
supervised-выбор. Основной автоматический результат явно экспортируется в
`automatic_metrics`; это те же числа, что в `diagnostic_metrics.kneedle_common_grid`,
а не дополнительный независимый метод. Frozen measurement plan задаёт
`primary_automatic_metric=kneedle_common_grid`. Узкая сетка не подставляется
в основной результат при плохом качестве широкой. Ошибки Kneedle на общей
сетке являются результатами метода и не блокируют честное сравнение.

Kneedle0.8.6 фиксирован; S1, convex/decreasing, online=false, interp1d.
При отсутствии knee pointwise-метод возвращает ambient dimension, как прежний
baseline. MAE включает все запросы, в том числе fallback. `fallback_n` считает
отказы, `boundary_n` — найденные knees на концах сетки, `selected_lambda_counts`
сохраняет распределение выбранных масштабов. Граница не переименовывается в
отказ задним числом. Полные кривые, индексы и флаги сохранены в
`test_scale_curves.npz`, ответы/цели/ID — в `test_predictions.npz`.

Для E1/E5 сохраняется прежний mean-Kneedle на50 кандидатах полного диапазона;
узкая22-точечная сетка к нему не относится. Перед обучением зависимой ячейки
проверяются артефакты reference, допустимость масштаба и одинаковый бюджет.
Копия reference receipt сохраняется с хешем. Отказ переносит обе причины:
`reference_selection_failed` и исходную `reference_failure_reason`.
Завершённое обучение с отказом выбора остаётся отсутствующим LID-измерением:
`measurement_status=selection_failed`, пустые метрики. Никакой λ по умолчанию
не подставляется. Агрегация показывает `coverage` для selected, scale_unresolved
и selection_failed и возвращает `complete_with_selection_issues`, если не все
выборы успешны и разрешены по границе.

Перед публикацией `complete.json` runner повторяет выбор по сохранённому holdout,
проверяет идентичность frozen receipt и пересчитывает все метрики/pointwise
решения из массивов. Агрегатор повторяет эти проверки и сверяет reference-цепочки.
Это проверка согласованности артефактов, не доказательство качества обучения.

### Полный экспорт измерений

Исполняемый протокол `dataset_routed_native_comparison_outputs_v4` добавляет
учёт E1/E5 и дополнительные readout; обучение и правила выбора из v3 сохранены.
У native RF, bridge и шести affine-FM интерфейсов `response` считается на том же
checkpoint и выбранном для `full` масштабе. Это зависимое дополнительное чтение,
а не ещё одна модель; отдельного подбора λ для него нет. Автоматический Kneedle
по-прежнему оценивает основной full/OLS5 readout. NF дополнительно сохраняет
точную производную, как прежде.

В E1 `reference_metrics` хранит разность среднего LID текущей и reference-модели
на идентичных test-данных. `n_source_train` означает исходное число обучающих
объектов до fit/holdout-разбиения; размеры реально использованных частей также
сохраняются. В E5 для каждой исходной строки считается
`d_i = prediction_transformed_i - prediction_reference_i`, затем
`MAE_delta = mean(abs(d_i - expected_lid_delta))`. Усреднение предсказаний перед
взятием модуля здесь недопустимо. Сохраняются class labels, проверяются число и
порядок query IDs и labels; копия reference-предсказаний связана хешем с receipt.
Идентичность пар опирается на порядок строк канонического архива: совпадение
повторяющихся class labels само по себе не доказывает совпадение изображения.
Используйте неизменённые массивы из проверенного канонического архива.

Все reference-метрики пересчитываются перед завершением ячейки и при агрегации.
Экспорт содержит effective true-LID mean/min/max для известных целей и не
приписывает абсолютный true LID E1/E5. Неизвестна именно абсолютная размерность;
ожидаемые изменения E5 задаются протоколом преобразования.

Агрегация создаёт JSON, соседний `*.results.csv` со всеми измеренными ячейками
и `*.scores.csv` с шестью показателями прежней таблицы в длинном формате:

- Known-LID: среднее `log(1 + MAE / abs(mean(true_LID)))` сначала по ячейкам
  внутри suite, затем поровну по пяти suite; итог `exp(mean) - 1`.
  Отдельно coefficients и dataset, по семь канонических ячеек.
- Arrows: отдельный MAE против номинальных известных целей.
- E1: трапециевидный интеграл `log(1 + abs(mean_delta_error/reference_mean))`
  по `log2(max(n_source_train)/n_source_train)`, делённый на длину интервала;
  затем `exp(value) - 1`. Используются все13 условий. При нулевом reference mean
  относительный показатель не определён: числовое значение пустое, причина явная.
- E5: `exp(mean(log(1 + MAE_delta))) - 1` отдельно для четырёх инвариантных и
  двух увеличивающих размерность преобразований, без reference-строки.

Все шесть показателей лучше при меньшем значении. Основной supervised и основной
common-grid Kneedle разделены явными protocol ID; E1/E5 в обеих таблицах используют
одни и те же reference-измерения. Старый narrow Kneedle есть только в подробном
историческом треке. Generated E3/E4 не смешиваются с35 каноническими ячейками.
Таблицы содержат все13 основных интерфейсов и дополнительные зависимые readout;
выбор восьми строк для человеческой редакции рукописи не выполняется автоматически.

Отказ выбора не выбрасывает ячейку из среднего: весь соответствующий показатель
получает `selection_failed` без числа. Неполное покрытие также не получает среднее
по оставшимся ячейкам. Граничный supervised выбор остаётся численным результатом
и отдельно учитывается в `boundary_selected_cells`; pointwise fallback включён
в MAE, его количество сохраняется. Старый `paper/unified_results.csv` не заменяется.

## Команды

Проверить все маршруты архитектуры, не запуская обучение:

```bash
python -m experiments.fair_campaign matrix --output artifacts/fair/matrix.json
```

Запустить одну ячейку нового сравнения:

```bash
CUDA_VISIBLE_DEVICES=0 python -m experiments.fair_campaign run \
  --variant vp_diffusion --cell e2/e2_arrows/dataset \
  --canonical-root data/lid_benchmarks_exact/benchmarks \
  --output artifacts/fair/runs/vp_diffusion/e2_arrows_dataset
```

Синтаксис одинаков для всех 13 вариантов, перечисленных в `matrix.json`.
Для E3/E4 укажите `--generated-root data/generated_benchmarks`. Запускайте
независимые ячейки на разных GPU; reference-ячейки должны закончиться раньше
зависимых. Например, для E1 шага2 добавляется
`--reference artifacts/fair/runs/vp_diffusion/e1_step1/complete.json`.
Каждый output должен быть новым; исходные checkpoints и progress сохраняются.

Короткая техническая проверка: к той же команде добавьте `--preflight --steps 20`
и отдельный output. Она использует ограниченные подмножества fit/holdout/test
и сокращённый бюджет; **такие результаты запрещены в benchmark-агрегации**.

Агрегация после завершения полной выбранной матрицы:

```bash
python -m experiments.fair_campaign aggregate \
  --root artifacts/fair/runs --scope all --output artifacts/fair/results.json
```

`--scope known_lid` проверяет полный Known-LID поднабор. Агрегатор требует все
сочетания, единые исходники/протокол, правильные бюджеты, фактические configs,
согласованные данные/индексы/нормировку/test-count, сохранённые веса и неизменные
selection/prediction receipts. Он отклоняет старые результаты, незавершённую
матрицу, дубликаты и preflight. Результаты прежних диагностик не становятся
новыми результатами от одного изменения конфигурации: нужен реальный перезапуск.

Отдельно проверить воспроизводимость измерений завершённого запуска, включая
явно помеченный preflight:

```bash
python -m experiments.fair_campaign verify --receipt artifacts/fair/runs/example/complete.json
```

Проверки нового кода:

```bash
python -m pytest -q tests/unit/test_fair_comparison.py tests/unit/test_fair_measurements.py tests/unit/test_fair_outputs.py tests/unit/test_non_gaussian_fields.py
```

Они проверяют все маршруты, сопоставление параметров, одинаковые нативные
posterior/Jacobian после преобразований, сохранение Arrows VE/RF формул и
градиентов, обратимость NF и соответствие полного determinant автодифференцированию.

## t-Flow и PFGM++

Протокол v6 сохраняет варианты `t_flowmatching` и `pfgmpp` из
`non_gaussian.yaml`, добавленные в v5. Старые11 методов сохраняют свои targets,
общий optimizer и шкалы; все13 используют новое full-ambient правило архитектуры.
Для новых вариантов синтаксис
`fair_campaign run` тот же, например `--variant t_flowmatching`.

Оба ядра — **радиальные многомерные Student-t**, с одним общим chi-square
знаменателем на объект. У t-Flow фиксировано nu5, у PFGM++ augmented dimension128
(эквивалентно Student-t nu128). Это два нативных метода одной семьи ядер.
Параметры хвостов не подбираются по датасету или LID.

[t-Flow, Appendix B, Eq.164–166](https://arxiv.org/html/2410.14171v2) использует
равномерное нативное время и noise MSE.
[PFGM++, Eq.4–6](https://proceedings.mlr.press/v202/xu23m/xu23m.pdf) использует
радиальное поле Пуассона и
[EDM objective](https://github.com/Newbeeer/pfgmpp/blob/main/training/loss.py).
Lognormal sigma переводится из sigma_data=.5 в общие fit-RMS единицы sigma_data=1:
mean=-1.2+log(2), std=1.2. Распределение условно ограничено общей поддержкой через
inverse CDF; радиусы шума и хвосты не обрезаются. Нативные sampling/loss являются
явными различиями методов; сравнение не изолирует только форму ядра.

Общий физический lambda означает RMS шума **на одну ambient координату**.
Student scale sigma=lambda*sqrt((nu-2)/nu), PFGM radius r=lambda*sqrt(nu-2).
Нативное время t-Flow равно k/(k+lambda), где k=sqrt(nu/(nu-2)). У прежних
Gaussian моделей lambda и обе29-точечные сетки не меняются.

Нативное Student-t ядро применяется во всей ambient размерности. Все координаты
идут в общий core или U-Net; posterior на нормальных направлениях не задаётся
аналитически. Условный Student kernel старой covariance-оболочки сохранён только
для загрузки и проверки исторического кода, не для новых benchmark запусков.
Core и число параметров совпадают с общими Gaussian полями на том же представлении.

Основной readout новых моделей — только `response=trace(Db)`, где b — posterior
mean. Он равен `N*t+t*(1-t)*div(v)` для t-Flow и `N-r*div(u)` для PFGM++.
Gaussian `full`, `fm_to_score` и likelihood-подстановка явно отклоняются.
Holdout MAE и Kneedle выбирают масштаб по этому нативному response; результат
хранится в `metrics.response`. Малый MAE при выбранном масштабе сам по себе
не доказывает точность в пределе lambda к нулю.

Для прямого API вызова используйте
`training.predict_lid(result, raw_query, lambda_rms, readout='response',
divergence_backend='exact', trace_probes=0)` на полном векторе;
для изображений используйте `divergence_backend='hutchinson', trace_probes=64`.
он сам применяет сохранённую нормировку. У новых классов `model.forward(y, lambda)`
возвращает posterior mean в канонических нормированных координатах. Нативная
скорость доступна через `model.native_velocity(state, t)`, радиальное поле —
через `model.poisson_radial_field(y, r)`; эти низкоуровневые методы также работают
в нормированных координатах. Их поле нельзя получать, просто переименовав
posterior-выход `forward` в velocity или score.
